## Current backend observations independently inspected for this packet

On 2026-11-07 the writing audit read the actual result file
`.cache/chorus-review/chorus-persistence/results.json` and
`chorus-state-pass.log`; these are ignored working artifacts, not permanent
submission links. The state suite recorded eight passing checks. The process
report recorded thirteen passing HTTP/SSE/restart assertions on isolated
`http://127.0.0.1:18886`, two independent cookie jars and server PIDs
7623 → 7624 → 7625 using one continuously preserved scratch database.

The process report checks shared-cookie identity, same-author versus
cross-author work changes, duplicate HTTP delivery, disconnection/reconnect,
two actual process restarts, unchanged durable rows at startup, an idempotent
retry after restart, removed-parent history and refusal to recreate a removed
source through a late response. Four local stream-update measurements were
2.63, 2.71, 1.97 and 2.03 ms. These measurements stop at the SSE observer;
they do not include visual presentation, a remote network or novice behaviour.
The report explicitly marks `browserUI: false` and `audioAudition: false`.

At inspection the implementation included uncommitted current work after
ADR026 / `5d696e5`; these observations must be pinned to the final code and
copied into a durable release record by the integrator. They cannot establish
the later UI build's focus, two-size operability, actual WebAudio output,
artistic quality, unfamiliar-pair success or next-day persistence. Those remain
separate evidence obligations. The main acceptance table intentionally keeps
those cells open until their own observations exist.
